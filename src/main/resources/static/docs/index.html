Tester Calculator – Functional Specification

This document is the single source of truth for the behaviour of the Tester Calculator application. The interactive API explorer and the raw OpenAPI specification describe the same contract in machine-readable form. Anything the running application does differently from what is written here is a defect.

1. Overview

The calculator evaluates arithmetic equations asynchronously. A client submits an equation together with a priority and immediately receives an operation id. The result is computed in the background after a delay that depends on the priority. The client polls the operation by id until the result (or an evaluation error) is available.

The service keeps all operations in memory. Restarting the application clears every operation.

3. Users and authentication

Every endpoint under /api/ requires HTTP Basic authentication, except GET /api/health. Static pages (/, /calculator.html, /docs/**, /openapi.yaml, /js/**, /css/**) are public.

  • Usernames and passwords are case-sensitive.
  • Missing or invalid credentials produce 401 with body {"code":"UNAUTHORIZED","message":"Valid credentials are required"}.
  • Operations are private to the user who created them. Reading, listing or deleting an operation that belongs to another user behaves exactly like an unknown id: 404 NOT_FOUND.

4. Equation grammar

An equation is a string of at most 200 characters (after no trimming; whitespace counts). It must not be blank.

ElementRuleExamples
NumbersNon-negative integers or decimals with . as the separator. A number has at most one dot. Leading dots are allowed (.5).42, 3.14, .5
Operators+ - * /2*3
ParenthesesAny depth; must be balanced.(1+2)*(3+4)
Unary minusAllowed before a number or an opening parenthesis, anywhere a value is expected, including the start of the equation.-3+5, 2*-3, -(2+3)
WhitespaceIgnored between tokens. 6 + 7

Evaluation rules

  • * and / bind tighter than + and -.
  • All binary operators are left-associative: 10-2-3 is (10-2)-3 = 5; 8/4/2 is 1.0.
  • Division is real-number division: 7/2 = 3.5, 1/3 = 0.3333333333333333.
  • Results are returned as JSON numbers with full double precision. Integral results are serialized with a .0 suffix (82.0, -5.0); compare them numerically, not as strings.

EquationResult
6+7+(3+4*5) * 382.0

position is the zero-based character offset in the submitted string where the problem was detected.

Evaluation errors (reported asynchronously)

Equations that are syntactically valid but cannot be evaluated are accepted (201) and finish with status FAILED. The only evaluation error is division by zero:

{"code":"DIVISION_BY_ZERO","message":"Division by zero"}

This applies to 1/0, 0/0, 5/(2-2) and so on.

5. Priorities, delays and status lifecycle

PriorityDelay until result
HIGH1 second
MEDIUM5 seconds
LOW15 seconds

If priority is omitted from the request body it defaults to MEDIUM. Any other value is rejected with 400 VALIDATION_ERROR.

Status lifecycle of an operation:

StatusWhen
PENDINGFrom submission until half of the delay has elapsed.
IN_PROGRESSFrom half of the delay until the full delay has elapsed.
DONEEvaluation succeeded; result is set, completedAt is set.
FAILEDEvaluation failed; error is set, result is null, completedAt is set.

The submission response contains estimatedCompletionAt = createdAt + delay. A tolerance of a few hundred milliseconds on top of the delay is acceptable; results must never be available before the delay.

GET/api/operations?page=0&size=20 – list my operations

Returns the caller's operations, newest first, regardless of status. Items use the same shape as the 200 body above (pending operations have result, error and completedAt set to null).

ParameterDefaultRule
page0Zero-based page index, ≥ 0. page=0 returns the newest size operations, page=1 the next ones.
size201–100
{"items": [ … ], "page": 0, "size": 20, "total": 37}

total is the total number of the caller's operations. A page beyond the end returns an empty items array. Invalid parameters produce 400 VALIDATION_ERROR.

DELETE/api/operations/{id} – delete my operation

StatusWhen
204 No ContentDeleted (any status, including pending ones)
401 UnauthorizedNo/invalid credentials
404 Not FoundUnknown id or the operation belongs to another user

After deletion, GET on the same id returns 404 and the operation disappears from the list.

GET/api/me – who am I

200 with {"username":"alice"}; 401 otherwise. The UI uses this endpoint to validate credentials on login.

GET/api/health – liveness

Public. Always 200 with {"status":"UP"}.

9. Suggested test areas

  • Authentication: every protected endpoint with no, wrong and correct credentials; case sensitivity; public endpoints.
  • Isolation: one user cannot read, list or delete another user's operations.
  • Submission: status code, response shape, validation of each field, boundary of the 200-character limit, default priority.
  • Parser: precedence, associativity, decimals, unary minus, parentheses, each documented syntax error and its position.
  • Evaluation: results of the documented examples, division by zero, precision.
  • Timing: response codes while pending (202 + Retry-After), status transitions, delay per priority, estimatedCompletionAt.
  • Listing: ordering, paging boundaries, total, parameter validation.
  • Deletion: effect on GET and on the list; deleting twice.
  • UI: login flow, error messages, submit/get-result flows, table rendering, logout.
  • Contract: compare real responses against openapi.yaml.
